# Spec: MCP tools

This contract governs the MCP tools that `protoc-gen-hearth-mcp` generates from
an app's agent RPCs, the JSON Schema each tool carries, the hints each effect
gives, the errors a tool call returns and the stdio server of an app. Consumers:
every app on hearth, the agents that lodge routes to it, the Go MCP SDK that
serves the tools, and the tests of all of them. The runtime is the Go package
`github.com/frostyard/hearth/mcpserver`.

## Interface

`protoc-gen-hearth-mcp` writes `<file>_hearth_mcp.go` into the Go package of each
proto file that holds a service with at least 1 agent RPC, and its first line is
`// Code generated by protoc-gen-hearth-mcp. DO NOT EDIT.`. For a service `S`:

| Generated | Shape |
| --- | --- |
| `type SAgentAPI interface` | 1 method for each RPC whose exposure holds `agent`: `<Rpc>(context.Context, *Req) (*Res, error)` |
| `const <s><Rpc>InputSchema` | the input schema of 1 tool, as 1 JSON string |
| `const <s><Rpc>OutputSchema` | the output schema of 1 tool, as 1 JSON string |
| `func STools(api SAgentAPI) []mcpserver.Tool` | the tools, in the RPCs' order |

| `mcpserver.Tool` field | Value |
| --- | --- |
| `Name` | the model's tool name: the RPC name in snake_case |
| `Description` | the RPC's `agent_description`, or its leading comment on 1 line, and then 1 line `Example input: <json>` per example |
| `Effect` | `EffectRead`, `EffectWrite` or `EffectOutward` |
| `InputSchema` | the JSON Schema of the request message |
| `OutputSchema` | the JSON Schema of the response message |
| `Call` | reads the arguments with `protojson.Unmarshal`, and calls the RPC |

A tool's arguments are 1 JSON object in the proto3 JSON form of the RPC's
request. The result is the response in the same form.

| Go | Meaning |
| --- | --- |
| `mcpserver.NewServer(impl *mcp.Implementation, caller authz.Caller, tools ...[]Tool) *mcp.Server` | 1 MCP server with the tools, and the caller of each call |
| `mcpserver.Annotations(Effect) *mcp.ToolAnnotations` | the hints of 1 effect |
| `mcpserver.ServeStdio(ctx, server, in io.ReadCloser, out io.WriteCloser) error` | the stdio transport: newline-delimited JSON over 2 streams, with no token |

### The schema mapping

| Proto | JSON Schema |
| --- | --- |
| `int32`, `sint32`, `sfixed32`, `uint32`, `fixed32` | `{"type": "integer"}` |
| `int64`, `sint64`, `sfixed64` | `{"type": "string", "pattern": "^-?[0-9]+$"}` |
| `uint64`, `fixed64` | `{"type": "string", "pattern": "^[0-9]+$"}` |
| `float`, `double` | `{"type": "number"}` |
| `bool` | `{"type": "boolean"}` |
| `string` | `{"type": "string"}` |
| `bytes` | `{"type": "string", "contentEncoding": "base64"}` |
| an enum | `{"type": "string", "enum": [<value names>]}` |
| a repeated field | `{"type": "array", "items": <the value's schema>}` |
| a map | `{"type": "object", "additionalProperties": <the value's schema>}` |
| a message | an object with its fields' JSON names, and `"additionalProperties": false` |
| `google.protobuf.NullValue` | `{"type": "null"}`, also as a repeated element and as a map value |
| a message that reaches itself | 1 definition under `$defs`, keyed by its full name, and `{"$ref": "#/$defs/<full name>"}` |
| a real oneof | `{"oneOf": [{"required": [a]}, {"required": [b]}, {"not": {"anyOf": [{"required": [a]}, {"required": [b]}]}}]}`: none or exactly 1 of its fields. Several oneofs are 1 entry each in `allOf` |
| a proto3 optional field | its scalar's schema, and no oneof constraint (its oneof is synthetic) |

| Well-known type | JSON Schema |
| --- | --- |
| `google.protobuf.Timestamp` | `{"type": "string", "format": "date-time"}` |
| `google.protobuf.Duration` | `{"type": "string", "pattern": "^-?[0-9]+(\\.[0-9]+)?s$"}` |
| `google.protobuf.FieldMask` | `{"type": "string"}` |
| `google.protobuf.Struct` | `{"type": "object"}` |
| `google.protobuf.Value` | `{}`: any JSON value |
| `google.protobuf.ListValue` | `{"type": "array"}` |
| `google.protobuf.Empty` | `{"type": "object"}` |
| `google.protobuf.NullValue` | `{"type": "null"}` |
| `google.protobuf.DoubleValue`, `FloatValue` | `{"type": "number"}` |
| `google.protobuf.Int64Value`, `UInt64Value` | `{"type": "string", "pattern": "^-?[0-9]+$"}` |
| `google.protobuf.Int32Value`, `UInt32Value` | `{"type": "integer"}` |
| `google.protobuf.BoolValue` | `{"type": "boolean"}` |
| `google.protobuf.StringValue` | `{"type": "string"}` |
| `google.protobuf.BytesValue` | `{"type": "string", "contentEncoding": "base64"}` |
| `google.protobuf.Any` | `{"type": "object"}`; an agent RPC must not carry 1 ([specs/options.md](options.md), rule 6) |

A tool's arguments and its result are JSON objects, so the RPC's request message
and its response message must have a JSON object form. `Struct` and `Empty` are
objects, and they are allowed. A well-known type that protojson reads and writes
as a string, a number, an array or a JSON null — `Timestamp`, `Duration`,
`FieldMask`, `Value`, `ListValue`, and every wrapper type — has no such form, and
the plugin refuses such an RPC with
`<rpc>: an agent RPC's request <type> has no JSON object form`, or the same for
the response.

The root of every schema is an object: it carries
`"$schema": "https://json-schema.org/draft/2020-12/schema"`, `"type": "object"`,
its `properties` and `"additionalProperties": false`. The bytes are canonical:
the object keys sorted, 2 spaces of indent, and no trailing newline, so 2 runs of
the generator write the same bytes. `internal/protoschema` builds them, and
`ForMessage(md protoreflect.MessageDescriptor) ([]byte, error)` is its whole
interface.

### The hints

| Effect | `readOnlyHint` | `destructiveHint` | `openWorldHint` |
| --- | --- | --- | --- |
| `read` | `true` | `false` | `false` |
| `write` | `false` | `false` | `false` |
| `outward` | `false` | `true` | `true` |
| an effect the package does not know | `false` | `true` | `true` |

All 3 are written explicitly, because the protocol reads an absent
`destructiveHint` or `openWorldHint` as `true`.

### The errors

| Case | Result |
| --- | --- |
| the arguments are no JSON object | `IsError: true`, 1 text content `invalid arguments: the arguments are not 1 JSON object` |
| the arguments do not fit the request | `IsError: true`, 1 text content `invalid arguments: <the decode error>` |
| a refused permission check | `IsError: true`, 1 text content `permission denied: needs <cap> on <selector>=<path>`, or `permission denied: needs <cap>` |
| an RPC that returns an error | `IsError: true`, 1 text content `<the error's text>` |
| a call that succeeds | `structuredContent` is the response as 1 JSON object, and `content` holds 1 text content with the same JSON |

A tool error is no protocol error: the agent reads the text and can correct its
call.

## Rules

- A tool exists for each RPC whose exposure holds `agent`, and for no other RPC.
  An RPC that only the UI reaches is in no tool and in no agent API.
- A tool's name is the model's tool name, so the name in the manifest, in the
  generated code and in the tool list is 1 string.
- A tool's effect is the RPC's effect, and its hints are that effect's hints.
- A tool call runs with the caller of its server: the server puts
  `authz.WithCaller(ctx, caller)` before it calls the tool, so the generated
  permission check reads that caller.
- 1 server has 1 caller for every call. A server that acts as the local user is
  never shared with a caller that lodge authenticated: lodge sets the caller of
  the app's API per request on the lodge socket, and an agent that lodge routes
  reaches the app's API, not its MCP server. A transport that authenticates each
  MCP call and picks the caller per call is a later phase.
- The stdio server needs no token: the app builds it with `authz.LocalCaller()`,
  so each call runs as the local user with the local grant.
- Each example of an agent RPC fits the tool's input schema, and the plugin
  refuses an example that does not, with
  `<rpc>: example <i> is no call of the tool "<tool>": <detail>`: an agent reads
  the example, so it must be a call the tool accepts. An example writes 1 path
  with its leading `/` and the JSON names of the fields.
- An app passes its generated tools the API that its permission check wraps, so
  a call is checked before the handler runs.
- The tools take a Go interface: an in-process handler satisfies it, and so does
  a client of the same RPCs.
