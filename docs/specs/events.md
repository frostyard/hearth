# Spec: Events

This contract governs an app's events: the CloudEvents envelope, the topic and
its path segments, the read filters of a grant, the code
`protoc-gen-hearth-events` generates, the outbox table, the relay, and the 2
transports. Consumers: every app on hearth (its handlers and its start-up),
lodge's broker and its consumers, and the tests of all of them. The runtime is
the Go package `github.com/frostyard/hearth/events` and its packages
`events/outbox`, `events/inproc` and `events/broker`.

## Interface

### The envelope

An event is 1 JSON object, CloudEvents 1.0 in its structured JSON form, with no
`data`. The members are written in this order:

| Member | Type | Required | Value |
| --- | --- | --- | --- |
| `specversion` | string | yes | `1.0` |
| `id` | string | yes | the event's own UUIDv7 (RFC 9562), lower-case `8-4-4-4-12` hex |
| `source` | string | yes | `/<app>` |
| `type` | string | yes | `org.frostyard.<app>.<object>.<verb>` ([specs/options.md](options.md), rule 10) |
| `subject` | string | yes | the object's id, not empty |
| `time` | string | yes | RFC 3339 with nanoseconds, in UTC |
| `author` | string | yes | the principal of the caller in the context, or `local` |
| `selector` | string | no | the object's canonical path; absent for an event with no selector |

```json
{"specversion":"1.0","id":"019a8b6e-6a00-7000-8000-000000000001","source":"/demo","type":"org.frostyard.demo.note.created","subject":"n-1","time":"2026-11-16T07:00:00Z","author":"chani","selector":"/work/2026"}
```

| Go | Meaning |
| --- | --- |
| `events.Event` | the envelope's members, and `Topic`, which is not in the envelope |
| `Event.MarshalJSON()` | the envelope, in the order above |
| `events.Parse([]byte) (Event, error)` | reads 1 envelope strictly; its `Topic` is empty |
| `events.Spec` | 1 event type: `App`, `Type`, `Topic` (with no path), `Selector`, `ReadPermission` |
| `events.New(ctx, spec, subject, path)` | builds 1 event, with the time and the id of now |
| `events.NewAt(ctx, spec, subject, path, now, random)` | builds 1 event with a given time and random source |
| `events.ErrNoCaller` | the error that a context with no caller gives |
| `Event.Validate()` | every required member set, the topic at most `MaxTopicLen`, the id a UUID, and the envelope at most `MaxEnvelopeLen` |

### The topic

| Event | Topic |
| --- | --- |
| no selector | `<app>.<object>.<verb>` |
| a selector, the root path `/` | `<app>.<object>.<verb>.<selector>` |
| a selector, the path `/<s1>/…/<sN>` | `<app>.<object>.<verb>.<selector>.<e(s1)>.….<e(sN)>` |

`e(s)` is `events.EncodeSegment(s)`: every byte of the segment's UTF-8 outside
`[A-Za-z0-9-]` becomes `%` and 2 upper-case hex digits.

| Path | Topic of `demo.note.created.group` |
| --- | --- |
| `/` or absent | `demo.note.created.group` |
| `/work` | `demo.note.created.group.work` |
| `/Work Notes/2026_Q1` | `demo.note.created.group.Work%20Notes.2026%5FQ1` |
| `/Cafe\u0301` (NFD) | `demo.note.created.group.Caf%C3%A9` |
| `/v1.2` | `demo.note.created.group.v1%2E2` |

`events.TopicOf(spec, path)` returns the topic and the canonical path.

### The read filters

`events.ReadFilters(specs []Spec, item authz.Item) ([]string, error)` returns
the filters of 1 grant item over an app's event specs, in the order of the
specs. Only a spec whose `ReadPermission` is the item's `Cap` gives filters; T
is its topic, and G the item's path for the spec's selector (the root when the
item names none):

| Spec | Item | Filters |
| --- | --- | --- |
| a selector | G is the root | `T` and `T.>` |
| a selector | G is a path | `T.<e(G)>` and `T.<e(G)>.>` |
| no selector | | `T` |
| any | names another selector at a path below the root | none |

No spec of the item's capability gives an empty list. An invalid spec or path
is an error.

`events.Match(filter, topic)` matches as NATS does: `*` is exactly 1 token, and
`>` as the last token is 1 or more tokens. `events.ValidFilter(filter)` refuses
an empty filter, an empty token, a space, and a `>` before the last token.

### The generated code

`protoc-gen-hearth-events` writes `<file>_hearth_events.go` into the Go package
of each proto file that holds at least 1 message with `hearth_event`, nested
messages included, and no file for any other. Its first line is
`// Code generated by protoc-gen-hearth-events. DO NOT EDIT.`. For each event
message, of Go name `M`, in the file's order:

| Generated | Shape |
| --- | --- |
| `var EventM = events.Spec{…}` | the event's app, type, topic, selector and read permission |
| `func NewM(ctx context.Context, subject, path string) (events.Event, error)` | with a selector: `events.New(ctx, EventM, subject, path)` |
| `func NewM(ctx context.Context, subject string) (events.Event, error)` | with no selector: `events.New(ctx, EventM, subject, "")` |
| `func EmitM(ctx context.Context, w events.Writer, subject, path string) error` | with a selector: `NewM`, then `w.Write` |
| `func EmitM(ctx context.Context, w events.Writer, subject string) error` | with no selector: `NewM`, then `w.Write` |

The plugin takes the parameters of a Go plugin
([specs/options.md](options.md#a-go-plugins-parameters)).

### The outbox

```sql
CREATE TABLE IF NOT EXISTS hearth_outbox (
	seq   INTEGER PRIMARY KEY AUTOINCREMENT,
	id    TEXT NOT NULL UNIQUE,
	topic TEXT NOT NULL,
	event BLOB NOT NULL
)
```

| Go | Meaning |
| --- | --- |
| `events.Writer` | `Write(ctx, Event) error`: writes 1 event in the change's transaction |
| `outbox.Schema` | the statement above |
| `outbox.Init(ctx, db)` | runs `Schema` |
| `outbox.Tx(tx *sql.Tx) events.Writer` | the outbox of 1 transaction: inserts the event's id, topic and envelope |
| `outbox.NewRelay(db, transport, outbox.Options{Interval, Batch, Logger})` | the relay of 1 database |
| `Relay.Drain(ctx) (int, error)` | publishes every row, in `seq` order, and returns how many |
| `Relay.Notify()` | wakes `Run`, and never blocks |
| `Relay.Run(ctx) error` | drains at once, on each `Notify`, and on each `Interval` (5 s by default), until `ctx` ends |

### The transports

| Go | Meaning |
| --- | --- |
| `events.Transport` | `Publish(ctx, Event) error`: returns nil only once the transport holds the event |
| `inproc.New()` | the in-process bus of a standalone app |
| `Bus.Subscribe(filter, handle) (cancel, error)` | calls `handle` for each event whose topic `filter` matches |
| `broker.Dial(broker.Options{Socket, User, Name, Timeout, ReconnectWait, Logger})` | a NATS connection over 1 Unix socket, such as lodge's `/run/lodge/nats.sock`, which reconnects when the broker comes back (`ReconnectWait`: nats.go's default when 0) |
| `Transport.Publish(ctx, e)` | validates `e`, then a JetStream publish of it, which waits for the `PubAck` |

A NATS publish has the subject `e.Topic`, the header `Nats-Msg-Id` set to
`e.ID`, the header `Content-Type: application/cloudevents+json`, and the
envelope as its data.

## Rules

### An event

- The author is the principal of `authz.CallerFrom(ctx)`. A context with no
  caller, or a caller with an empty principal, gives an error that wraps
  `events.ErrNoCaller`, and no event. No request field is read.
- `subject` is not empty; `id` is new for each event, so 2 events of 1 object
  have 2 ids, and `id` is never the subject.
- An event with a selector takes the canonical form of its path (`authz.CleanPath`:
  Unicode NFC, no empty, `.` or `..` segment, no trailing `/`); an empty path is
  the root. An invalid path is an error that wraps `*authz.PathError`.
- An event with no selector takes no path: a path that is not empty is an error.
- A topic longer than 1024 bytes (`events.MaxTopicLen`) or an envelope longer
  than 32 KiB (`events.MaxEnvelopeLen`) is an error, so the change that would
  write it fails in its transaction: a row that no broker takes would stop the
  relay. `NewAt`, `outbox.Tx(…).Write` and the NATS transport's `Publish` each
  run `Event.Validate`.
- `Parse` refuses an unknown member, a member name in another case, a
  duplicate member, a missing required member, a `specversion` other than
  `1.0`, and a `time` that is not RFC 3339.

### The outbox and the relay

- An event is written only through `outbox.Tx`, in the transaction of the
  change it reports: it commits with the change, or rolls back with it.
- The relay publishes rows in `seq` order and deletes a row only after its
  transport's `Publish` returned nil. A failed `Publish` stops the drain, and
  that row and every later row stay for the next drain.
- A stop at any step loses no event: a stop after the commit and before the
  publish leaves the row; a stop after the publish and before the delete
  publishes the event again, with the same `id`.
- 1 relay drains 1 database.

### The transports

- The in-process bus calls each handler on the publisher's goroutine, in the
  order of the subscriptions, outside its own lock, so a handler may subscribe
  or publish. It skips an `id` among the last 1,024 ids it delivered.
- The NATS transport treats a `PubAck` that reports a duplicate as success: the
  stream holds the event once.
- The NATS transport only publishes. A consumer subscribes through lodge, which
  gives it the read filters of its grant.
- Delivery is at least once. A consumer de-duplicates by `id`.
