# Spec: Permissions

This contract governs an app's permission check: the format of a grant, the
rules of a path, the check that a call runs, the code `protoc-gen-hearth-authz`
generates, the errors it returns and the headers `lodge/` reads. Consumers:
every app on hearth (its handlers and its hooks), lodge's adapter, the MCP
tools, and the tests of all of them. The runtime is the Go package
`github.com/frostyard/hearth/authz`.

## Interface

### A grant

A grant is a JSON array of items, and the reader is strict: an unknown member is
an error.

```json
[
  {"cap": "demo:read", "sel": {"group": "/work"}},
  {"cap": "demo:write"}
]
```

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `cap` | string | yes | `^[a-z][a-z0-9]{0,15}:[a-z][a-z0-9_]*$`: the app's id, `:`, and the capability |
| `sel` | object of string to string | no | each key matches `^[a-z][a-z0-9_]*$`; each value is a valid path |

| Go | Meaning |
| --- | --- |
| `authz.ParseGrant([]byte) (Grant, error)` | reads and validates the JSON array |
| `authz.NewGrant(...Item) (Grant, error)` | validates items that the app builds |
| the package's `Local()` | the local user's grant: every capability on the root path |
| `Grant.Items() []Item` | the items, copied |
| `Grant.MarshalJSON()` | the JSON array of items; the local grant writes `[]`, and a marshalled local grant allows nothing |
| the zero `Grant` | allows nothing |

### A path

An absent selector value is the root path. The app substitutes the root before it
calls the runtime, and `CleanPath("")` is an error.

| Rule | Example |
| --- | --- |
| the Unicode NFC form of the path is the compared form | a grant on `/Café` (U+00E9) covers a request `/Cafe\u0301` (U+0301), and the reverse |
| a path starts with `/` | `/work` is a path, `work` is not |
| `/` alone is the root | the root covers every path |
| no empty segment | `/a//b` is an error |
| no `.` segment and no `..` segment | `/a/../b` is an error |
| no trailing `/` | `/a/` is an error |
| the path is compared segment by segment | a grant on `/Chan` covers `/Chan` and `/Chan/2026`, and never `/Chani` |

`authz.CleanPath(string) (string, error)` returns the canonical form, and an
`*authz.PathError` whose text is `invalid <selector> path "<path>": <reason>`
(`invalid path "<path>": <reason>` with no selector) for an invalid 1.

### A check

| Call | Passes when |
| --- | --- |
| `Grant.Check(cap, Sel{Selector, Path}, ...)` | 1 item covers each value (see the rules) |
| `Grant.Check(cap)` | 1 item with `cap` holds the root path for every selector it names, or names none |
| `Grant.CheckAny(cap)` | 1 item holds `cap` on any path |
| `Grant.Allows(cap, selector, path) bool` | `Check` on that 1 value passes; an invalid path allows nothing |

`Sel` is 1 selector value: `authz.Sel{Selector: "group", Path: "/work"}`. An
empty `Path` is the root.

An item covers 1 selector value when all of these hold:

1. the item's `cap` is the capability of the check;
2. the item's path for the value's selector (the root when the item names no such
   selector) covers the value's path;
3. for every other selector the item names, the item's path covers every value
   of that selector in the same check, and the root when the check carries none.

The local grant passes every check, after the request's paths are validated.

### The errors

| Error | Text |
| --- | --- |
| a refused value | `permission denied: needs <cap> on <selector>=<path>` |
| a refused check without a selector | `permission denied: needs <cap>` |
| an invalid request path | `invalid <selector> path "<path>": <reason>` |
| no caller in the context | `permission denied: no caller` |

The refused value is the first value that no item covers, and `<path>` is its
canonical form.

### The caller

| Go | Meaning |
| --- | --- |
| `authz.Caller{Principal, Grant}` | who calls, and what bounds it |
| `authz.LocalCaller()` | the principal `local` with the local grant |
| `authz.WithCaller(ctx, Caller)` | the context that carries the caller |
| `authz.CallerFrom(ctx) (Caller, bool)` | the caller, and whether the context carries 1 |
| `authz.GrantFrom(ctx) (Grant, error)` | the caller's grant, or `permission denied: no caller` |

A context with no caller refuses every check: the runtime fails closed.

### The transaction

| Go | Meaning |
| --- | --- |
| `authz.TxFunc[Tx]` | `func(ctx, func(ctx, Tx) error) error`: the app's transaction |
| `authz.WithTx(ctx, tx)` | the context that carries the transaction value |
| `authz.TxFrom[Tx](ctx) (Tx, bool)` | the transaction value, and whether the context carries 1 |

2 transaction types are 2 different context values.

### The generated code

`protoc-gen-hearth-authz` writes `<file>_hearth_authz.go` into the Go package of each
proto file that holds a service, and its first
line is `// Code generated by protoc-gen-hearth-authz. DO NOT EDIT.`. For a
service `S` (its Go name):

| Generated | Shape |
| --- | --- |
| `type SAPI interface` | 1 method for each unary RPC: `<Rpc>(context.Context, *Req) (*Res, error)` |
| `type SAuthorizer[Tx any] interface` | 1 method for each RPC on an object id: `Authorize<Rpc>(ctx context.Context, tx Tx, grant authz.Grant, req *Req) error` |
| `type SImpl[Tx any] interface` | `SAPI` and `SAuthorizer[Tx]` |
| `func CheckS<Rpc>(grant authz.Grant, req *Req) error` | the check of 1 RPC (see the rules) |
| `func NewSAuthz[Tx any](impl SImpl[Tx], inTx authz.TxFunc[Tx]) SAPI` | the API with the checks |

The plugin refuses a streaming RPC, because 1 permission check reads 1 request.
`NewSAuthz` panics when the service has an RPC on an object id and `inTx` is nil.
For an RPC on an object id, the wrapper's method:

1. reads the grant with `authz.GrantFrom`;
2. runs the generated check;
3. calls `inTx`, and inside it calls `impl.Authorize<Rpc>`, then the RPC with
   `authz.WithTx(ctx, tx)`;
4. returns the RPC's response, or its error, and never a response with another
   error.

For every other RPC the method reads the grant, runs the check and calls the RPC
with the caller's context.

### The headers, and the sockets

| Header | Value |
| --- | --- |
| `Lodge-Principal` | the principal: `^[A-Za-z0-9@._-]{1,64}$` |
| `Lodge-Grant` | the grant's JSON as base64url without padding (RFC 4648 §5) |

| Go | Meaning |
| --- | --- |
| `lodge.Listener(l, lodgeUID)` | accepts only the connections of the user `lodgeUID`, and closes every other connection before it reads a byte |
| `lodge.ConnContext` | marks the context of a connection from that listener; it is `http.Server.ConnContext` |
| `lodge.Handler(next)` | reads the 2 headers on a marked connection, and refuses with 403 and 1 line otherwise |
| `lodge.PrivateHandler(next)` | deletes every `Lodge-*` header, and sets the local user's caller |
| `lodge.Serve(l, lodgeUID, h)` | `Listener` + `ConnContext` + `Handler` on 1 `http.Server` |

## Rules

- A granted path covers a requested path when they are equal, when the request is
  below the grant, or when the grant is the root.
- A check of several values needs an item that covers every 1 of them, and the
  grant is the union of its items.
- An item that names a selector covers no value of another check when the check
  carries no value of that selector: the absent value is the root, and only the
  root path covers the root.
- The request's paths are validated before any item is read: an invalid path is
  a `*PathError`, not a refusal.
- An RPC is on an object id when its request carries at least 1 object-id field:
  a singular field named `id` or ending in `_id` whose kind is not `message` or
  `group` (a `string`, `bytes`, an integer or an enum), followed through
  singular message fields, as a dotted path of proto field names. A map, a
  repeated field and a cycle are not followed.
- An RPC's generated check reads the request's selector fields
  ([specs/options.md](options.md), rule 7) when it has any, `CheckAny` when it has
  an object id and no selector field, and `Check` with the capability alone when
  it has neither.
- The peer check runs before any read: the listener closes a connection whose
  peer's user id is not `lodgeUID`, or cannot be read, and it keeps accepting. A
  platform that cannot read the peer's user id accepts nothing.
- `Lodge-Grant` is base64url without padding. Padded base64, another alphabet, or
  data that is no grant is refused with 403.
- On the lodge socket, a missing or malformed header is refused with 403 and 1
  line of `text/plain`. The handler never runs for a refused request.
- On the private socket, every `Lodge-*` header is deleted before the handler
  runs, and the caller is the local user's.
